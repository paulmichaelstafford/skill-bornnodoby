# Architecture review

Read-only. This skill reports; it never fixes, approves or signs.

## Inputs, in this order

1. `docs/architecture.generated.md` — the module map, what each module
   holds, the import matrix, where each feature lives.
2. `docs/guards.generated.md` — every guard test, its rule tests, and the
   burn-down lists with their current entries.
3. `docs/architecture.md` — the rulings behind the matrix and the kinds.
4. The diff: `git diff origin/<base>...HEAD`.

The first two are generated by `docs/tools/architecture-map.py` from the
sources. Never edit them by hand. If they are stale, run:

```sh
python3 docs/tools/architecture-map.py
```

A change to either generated file because the sources changed is part of the
PR; a diff in them with no source change is a finding.

## Procedure

### 1. Run the architecture guards

```sh
./gradlew :sim-scenario:test \
  --tests '*ArchitectureGuardTest' \
  --tests '*ArchitectureLayerGuardTest' \
  --tests '*ArchitectureStateGuardTest' \
  --tests '*ArchitectureMatrixGuardTest' \
  --tests '*ColumnsGuardTest' \
  --tests '*DoorTwoGuardTest'
```

Any failure is at least **Important**. Quote the failing test name and the
file/count it printed. Do not re-run other modules' tests.

### 2. Classify every changed file

For each file in the diff, read its module, package, feature and kind from
`docs/architecture.generated.md` ("What each module holds" and "Where a
feature lives"). A new file that does not appear there is **Important**:
either it is a new feature (its kind must be in
`style/feature-kinds.txt`, and the file is missing from the generated map) or
it is in the wrong package.

### 3. Check the imports against the matrix

For every added `import` line:

- find the importing file's kind and the imported file's kind;
- look up the cell in "The import matrix";
- `no` is **Critical**; `names only` and `(only itself)` require the exact
  exception the matrix states.

Common violations and what they look like:

| Added import | Verdict |
| --- | --- |
| a verb importing the engine, a noun, another verb, or the terrain | Critical |
| the engine importing a rule, a noun or a verb | Critical |
| a noun importing another noun | Critical |
| a rule or a config/values file importing above its layer | Critical |
| the wiring root importing a verb | Critical |
| a test or an app module used to justify a sim import | Critical |

An import the compiler already forbids (module edges) is not a finding; say
so and move on.

### 4. Check for weakened rules

Any of these is **Critical** regardless of the guard result:

- a new entry in `sim-scenario/src/test/resources/style/*` (a burn-down list
  only shrinks; a fixed violation must be struck, a new one is never added);
- a new exception in `docs/exceptions.md`;
- a `@Suppress`, a detekt baseline, or a disabled test;
- a change to a guard test or to the files in `docs/guarded-paths.txt`.

A guard-test or guarded-file change is out of scope for this skill: it needs
Paul's approval, so report it and stop.

### 5. Report

```markdown
VERDICT: PASS | FAIL
- [Critical|Important|Minor] file:line — finding — evidence (guard test, matrix cell, or rule)
```

PASS only when the guards are green, every import is allowed, no rule was
weakened, and the generated map is current. Otherwise FAIL, even for one
Minor finding — a reviewer may waive a Minor, the skill may not.

## What this skill does not judge

- Formatting, naming, detekt or ktlint: `quality-review`.
- Whether changed behaviour has a test: `light-tests-review`.
- Whether a rule change is desirable: that is Paul's, not the reviewer's.
